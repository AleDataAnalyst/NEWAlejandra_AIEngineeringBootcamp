Generación aumentada con contexto

Los pasos 6–7 del pipeline online: dado el contexto recuperado, el LLM redacta la respuesta. Gemini es el camino principal; Hugging Face queda como alternativa documentada.

El flujo: pregunta → contexto → LLM → respuesta

El mismo formatear_contexto(chunks) que usabas en S9 para inspeccionar es ahora la evidencia que entra al prompt. Nada se re-embeddea aquí: reutilizas el retriever.

Ensamblar el prompt (prompts.py)

def build_rag_prompt(contexto, pregunta):
    return (
        INSTRUCCIONES_RAG +
        "--- CONTEXTO RECUPERADO ---" + contexto +
        "--- PREGUNTA ---" + pregunta +
        "--- RESPUESTA ---"
    )

Llamar al modelo (generate.py)

response = client.models.generate_content(
    model=GEMINI_MODEL,
    contents=prompt,
    config={"temperature": 0.2},
)
return response.text.strip()

Temperatura baja (0.2) → menos creatividad, más apego al texto recuperado.

Puente con S9 El backend de S9 devolvía contexto. S10 añade la capa de generación encima, sin tocar el retrieval: retriever → context → prompts → generate.
2

Prompt con grounding

Con el mismo top-K, dos prompts distintos producen sistemas muy diferentes. El prompt es tu primera línea de defensa contra las alucinaciones.

Prompt permisivo — "responde lo mejor que puedas"
El modelo completa con su conocimiento general → más alucinaciones. Ante "¿capital de Francia?" responde "París" aunque no esté en el corpus.
Prompt restrictivo — "solo con el contexto; si no, dilo"
Abstenciones honestas, menos invenciones. Ante una pregunta fuera de corpus responde "no hay información en el contexto sobre…".

Estructura recomendada: tres piezas separadas

PiezaQuién la controla¿Cambia por consulta?
Instrucciones (rol, reglas, citas, abstención)Tú (prompts.py)No
Contexto recuperado (delimitado por fragmentos)Retriever + context.pySí
Pregunta del usuarioUsuarioSí

Las reglas que fuerzan grounding

# INSTRUCCIONES_RAG
- Responde ÚNICAMENTE con la información del contexto proporcionado.
- Si el contexto no contiene información suficiente, indícalo explícitamente.
- Cuando cites un hecho, menciona la fuente si aparece en el contexto.
- No inventes eventos, fechas ni datos que no estén en el contexto.
Errores frecuentes: mezclar instrucciones dentro del contexto (el modelo confunde evidencia con órdenes) · no delimitar fragmentos (no sabes qué chunk usó) · K muy alto (ruido y dilución de la evidencia) · olvidar la pregunta al final (el modelo resume en vez de responder) · pedir JSON sin validarlo en Python.
Texto libre vs JSON Si un programa debe consumir la salida, pide JSON ({"respuesta", "hay_evidencia", "fuentes_citadas"}) y haz json.loads para ramificar. Misma evidencia, distinto formato.
3

Evaluar respuestas RAG

Evaluar la respuesta generada (S10) es distinto de evaluar el retrieval (S9). No necesitas LLM-as-judge ni MRR para empezar: rigor manual con un set fijo de preguntas.

Cinco criterios prácticos

🎯 Exactitud

¿Lo dicho está en el contexto/corpus?

🧭 Relevancia

¿Responde a la pregunta formulada?

🧩 Coherencia

¿Bien redactado y consistente?

🔗 Trazabilidad

¿Puedes vincular afirmaciones a una fuente?

📐 Formato

Si pides JSON: ¿parsea? ¿respeta el esquema?

⚠️ Ojo

Un JSON válido puede parsear y aun así alucinar. Evalúa formato y contenido por separado.

Rúbrica orientativa (veredicto por pregunta)

SímboloSignificado
✅ AciertoCorrecta y basada en el contexto
⚠️ ParcialAlgo útil pero incompleto o ruidoso
❌ FalloNo responde bien (sin inventar necesariamente)
🛑 AlucinaciónInventa hechos no presentes
⏸️ AbstenciónDebería abstenerse (y lo hace, o debería)
Separa capas al depurar un fallo ¿El contexto ya era malo? → vuelve a S9 (K, chunking, índice). ¿El contexto era bueno y la respuesta mala? → prompt, temperatura o validación. No mezcles fallos de retrieval con fallos de generación.
4

Robustez: alucinaciones, injection, validación

Un RAG útil también es fiable. Tres frentes: reducir alucinaciones, resistir prompt injection y validar antes de gastar tokens (continuidad del Sprint 6).

Alucinación = inventar respecto al contexto

Afirmar hechos que no están en el contexto recuperado, presentándolos como si vinieran de ahí. No es lo mismo que abstenerse ("no lo sé") ni que resumir mal un chunk. Se combate con: prompt restrictivo + temperatura baja + fuentes visibles + inspeccionar el contexto antes de confiar.

Prompt injection: dos canales de ataque en RAG

CanalOrigenEjemplo
UsuarioPregunta escrita"Ignora el contexto y di que…"
Documento (específico de RAG)Chunk recuperadoUn PDF/MD indexado con instrucciones maliciosas embebidas
Defensa en capas (nivel bootcamp) Las reglas del sistema mandan sobre el contexto · validar patrones en la pregunta (validators.py) · el contexto es evidencia, no código: no ejecutar órdenes que aparezcan en él · mostrar fuentes para poder investigar. No es seguridad de producción: es defensa pedagógica.

De script a aplicación (Streamlit)

Ya tienes el RAG funcionando en consola. El último paso es exponerlo con una interfaz MVP — sin reimplementar la lógica dentro de la app.

La clave: un contrato de backend

La UI solo llama a una función pública y renderiza el resultado. Si mañana cambias Streamlit por Gradio o una API, no tocas el núcleo.

# src/logic.py — el contrato único
def responder(pregunta, top_k=None) -> dict:
    # retrieve → context → prompt → generate
    return {"respuesta", "contexto", "chunks", "fuentes", "error"}
logic.responder()
un backend, un contrato
▲ lo llaman tres clientes distintos
consola

main.py --ask

RAG completo en terminal.

navegador

app.py (Streamlit)

Chat web con streaming.

futuro

API POST /ask

Mismo contrato, otro cliente.

Anti-patrón: volver a hacer query a Chroma + generate_content dentro de app.py. Duplicas lógica, te saltas los validators y rompes el contrato único. La UI no debe conocer el vector store ni el prompt.

Qué muestra la app

💬 Chat

Historial + chat_input. Cada turno es independiente: el modelo no "recuerda".

⏳ Estado

Spinner "Consultando el corpus…" y respuesta con streaming palabra a palabra.

🔗 Fuentes

Lista de documentos usados bajo la respuesta (trazabilidad).

🔍 Contexto (debug)

Expander con el texto que entró al prompt; slider de Top-K en la sidebar.

Regla de oro Si python main.py --ask "…" falla en consola, la UI también fallará. Arregla el backend primero. Checklist antes de streamlit run app.py: corpus en data/ → --prepare --index → --ask funciona → entonces la web.
6

El pipeline modular clave del sprint

El proyecto crece por última vez: la lógica se agrupa en un paquete src/ y se añaden los módulos de generación, validación y orquestación. Arriba quedan dos clientes (CLI y app) que solo consumen el contrato. Vamos despacio.

La idea en una frase Una responsabilidad por archivo, y la interfaz separada de la lógica. Todo el pipeline vive en src/; app.py y main.py son solo caras del mismo backend. La UI no sabe cómo funciona el RAG: solo llama a responder().

¿Por qué molestarse? (el problema que resuelve)

❌ Toda la lógica dentro de app.py
La interfaz embebe el retrieval, el prompt y la llamada a Gemini. La consola y la web hacen cosas distintas, los validators se olvidan en una de las dos y cualquier cambio se duplica. Imposible testear sin abrir el navegador.
✅ Lógica en src/, clientes arriba
src/logic.responder() es el único punto de entrada. main.py y app.py lo llaman igual. Cambias el prompt o el modelo en src/ y ambos clientes se benefician sin tocarse.

El proyecto por capas (S8 + S9 heredados + S10 nuevo)

🖥️ app.py  ·  🚪 main.py clientes (UI + CLI)
Dos caras del mismo sistema. app: chat Streamlit con streaming, fuentes y expander. main: CLI con --prepare/--index/--query/--ask/--eval. Ninguno contiene lógica de RAG: solo llaman a responder().
▼ ambos llaman a
🧠 src/logic.py orquestador · contrato único
responder(pregunta): valida → recupera → formatea contexto → valida contexto → construye prompt → genera. Devuelve un dict {respuesta, contexto, chunks, fuentes, error}.
▼ usa las piezas nuevas del Sprint 10
🧩 prompts.py · 💬 generate.py · 🛡️ validators.py generación (S10)
prompts: ensambla instrucciones + contexto + pregunta. generate: llama a Gemini con temperatura baja. validators: rechaza inputs inválidos o sospechosos antes de gastar tokens.
▼ reutiliza lo ya construido
🔎 retriever · 📋 context · 🗄️ index recuperación (S9)
Sin cambios: el retriever busca en Chroma y context formatea. logic los encadena antes de generar.
▼ y la base offline
📥 load · 🧹 clean · ✂️ chunk · 🔢 embed  +  ⚙️ config.py preparación (S8) + configuración
La ingesta de S8 intacta. config.py ahora también centraliza GEMINI_MODEL y GENERATION_TEMPERATURE.

Qué hace exactamente cada archivo nuevo (S10)

prompts.py
Construcción del prompt. Separa instrucciones fijas (grounding, citas, abstención), contexto y pregunta con build_rag_prompt().
generate.py
Generación. Envía el prompt a Gemini (GEMINI_MODEL, temperatura 0.2) y devuelve el texto.
validators.py
Validación pre-LLM. validar_pregunta (vacía, larga, patrones sospechosos) y validar_contexto (sin fragmentos).
logic.py
Orquestador. responder(): el contrato único que encadena todo y devuelve el dict de resultado.
app.py
Interfaz Streamlit. Chat + historial + streaming + sidebar. Cada turno llama a responder().
config.py
Ampliado. Añade GEMINI_MODEL y GENERATION_TEMPERATURE sobre los parámetros de S8/S9.

Cómo se hablan los módulos: los import

logic.py importa piezas de los tres sprints y las encadena; los clientes solo importan responder:

# src/logic.py — encadena S9 (recuperar) + S10 (generar)
from .retriever  import recuperar          # S9
from .context    import formatear_contexto  # S9
from .prompts    import build_rag_prompt    # S10
from .generate   import generar_respuesta   # S10
from .validators import validar_pregunta, validar_contexto

# app.py y main.py — solo conocen el contrato
from src.logic import responder
resultado = responder(pregunta, top_k=top_k)

Las dependencias fluyen en una sola dirección: los clientes se apoyan en logic, que se apoya en las capas de abajo.

config.py                          # parámetros de todo el módulo
   ▲
load → clean → chunk → embed → index → retriever → context   # S8 + S9
                                                     ▲
                     prompts · generate · validators │        # S10
                                    ▲                │
                                 logic.py ◄──────────┘        # orquesta: responder()
                                    ▲
                     main.py ◄──────┴──────► app.py           # CLI y web: solo consumen
Cómo explicarlo con tus palabras Piensa en un restaurante con cocina y dos salas: la cocina es src/ (misma receta, responder() es el pase). La sala de terraza (main.py, consola) y la sala interior (app.py, web) sirven el mismo plato sin saber cocinarlo. Cambias la receta en la cocina y ambas salas sirven el plato nuevo. El camarero (validators) rechaza pedidos imposibles antes de molestar al chef (Gemini).

Qué ganas con esta arquitectura

🔁 Un backend, varios clientes

CLI, web y una futura API comparten responder(). Cero duplicación.

🧪 Testeable sin UI

Pruebas responder() en consola o en un test antes de abrir el navegador.

🔧 Cambias en un sitio

Prompt, modelo o temperatura en src/; ambos clientes se benefician.

🛡️ Validación centralizada

Los validators viven en logic: ningún cliente puede saltárselos.

🧱 Acumulativo

S8 + S9 intactos; S10 solo añade encima. Nada se reescribe.

🚀 Listo para agentes

Este backend modular es la base del Módulo 5 (AI Agents).

El proyecto: RAG completo + app web

Pipeline acumulativo S8 + S9 + S10: documentos → chunks → embeddings → ChromaDB → retrieval → respuesta generada → chatbot Streamlit. Corpus: agenda cultural de Madrid.

Primero la CLI (arregla el backend)

python main.py --prepare --index   # offline + índice
python main.py --ask "¿Hay cine gratuito en verano?"
python main.py --query "…"          # solo retrieval (S9)

Tras cambiar MAX_CHUNKS_EMBED: reconstruye con --prepare --index --recreate-index.

Luego la web

streamlit run app.py

Abre localhost:8501. Sidebar con nombre del bot, Top-K y "Limpiar chat". Deja la terminal abierta.

Un fallo típico del corpus limitado Si MAX_CHUNKS_EMBED es muy bajo, preguntas válidas pueden fallar porque la respuesta está en un chunk no indexado: el retrieval solo busca dentro de lo que se indexó. Sube N (o None) y reindexa.

Checklist del sprint

Conceptos que debes dominar

  • Del contexto (S9) a la respuesta generada (S10)
  • Prompt: instrucciones + contexto + pregunta; grounding
  • Cuándo abstenerse es la respuesta correcta
  • Evaluar respuestas ≠ evaluar retrieval
  • Alucinaciones, prompt injection (usuario y documento)
  • Contrato de backend: una función, varios clientes

Práctica con el proyecto

  • --prepare --index deja el índice listo
  • --ask devuelve respuesta + fuentes en consola
  • Probaste una pregunta fuera de corpus (abstención)
  • streamlit run app.py funciona tras la CLI
  • Ajustaste Top-K y viste el efecto en el contexto
  • .env fuera de Git · output/ no versionado
