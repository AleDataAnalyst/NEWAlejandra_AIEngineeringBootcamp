Idea que atraviesa todo el contenido SQL es declarativo: describes qué datos quieres, no cómo obtenerlos. Python solo hace de mensajero — conecta, envía la query como texto y recoge el resultado con el cursor.

Conexión y cursores

Antes de escribir una sola query necesitas dos cosas: una conexión a la base de datos y un cursor para ejecutar sentencias y recoger resultados.

Conexión

sqlite3.connect()

Abre (o crea si no existe) el fichero .db. ¡Cuidado! Si la ruta está mal, SQLite crea una base vacía en vez de dar error.

Cursor

connection.cursor()

El objeto que ejecuta las queries y recuerda la última consulta lanzada.

pandas

De tupla a DataFrame

El cursor devuelve tuplas; con cursor.description sacas los nombres de columna para construir un DataFrame legible.

El patrón que se repite en todo el contenido

connection = sqlite3.connect("data/chinook.db")
cursor_bootcamp = connection.cursor()

cursor_bootcamp.execute(query)         # ejecuta la query (no devuelve nada)
ans = cursor_bootcamp.fetchall()     # recoge TODAS las filas
names = [d[0] for d in cursor_bootcamp.description]  # nombres de columna
MétodoQué devuelve
fetchone()Una única fila (o None)
fetchmany(n)Las siguientes n filas
fetchall()Todas las filas restantes
Ojo Una vez haces fetchall(), el cursor se queda "vacío" para esa query — si lo vuelves a llamar, no hay nada más que traer.
Autocomprobación
1. ¿Qué método usarías para traer SOLO la primera fila de un resultado?
2. Conectas a una ruta de base de datos que no existe. ¿Qué ocurre?

Modelo de datos y primeras queries

Antes de consultar, entiende el schema: qué tablas hay y qué columnas tiene cada una. Luego, SELECT es la sentencia que usarás en el 90% de las queries.

SELECT campo1, campo2
FROM tabla
LIMIT 10;

SELECT *

Trae todas las columnas. Útil para explorar, pero evita en producción: trae más de lo necesario.

Selección de campos

SELECT nombre, precio FROM tabla — solo lo que necesitas.

LIMIT y DISTINCT

LIMIT acota el número de filas; DISTINCT elimina duplicados en el resultado.

Autocomprobación
1. ¿Qué hace DISTINCT?
2. SELECT nombre FROM clientes LIMIT 5 devuelve...

WHERE: filtrar resultados

WHERE filtra filas antes de que se devuelvan — el equivalente SQL de un df[df['columna'] > x] en pandas.

SELECT *
FROM tracks
WHERE Milliseconds > 300000
  AND GenreId = 1;

Filtros numéricos

>, <, =, BETWEEN...

Filtros sobre texto

LIKE '%patron%' para búsquedas parciales.

Combinaciones booleanas

AND, OR, NOT para condiciones compuestas.

Función muy práctica Antes de filtrar sobre una columna de texto, revisa sus valores únicos (DISTINCT) — evita sorpresas por mayúsculas, espacios o variantes de escritura.
Autocomprobación
1. ¿Cuál es el equivalente en pandas de WHERE precio > 10?
2. Para buscar texto que contenga "casa" en cualquier posición usarías...
4

Ordenación, agregación y agrupación

Tres piezas que casi siempre van juntas: ordenar el resultado, calcular funciones de resumen, y agruparlas por categoría.

Ordenar

ORDER BY

ORDER BY precio DESC — de mayor a menor.

Agregar

Funciones de agregación

COUNT, SUM, AVG, MIN, MAX — colapsan varias filas en un solo valor.

Agrupar

GROUP BY

Aplica la agregación por categoría en vez de sobre toda la tabla.

SELECT GenreId, COUNT(*) AS n_tracks, AVG(Milliseconds) AS duracion_media
FROM tracks
GROUP BY GenreId
ORDER BY n_tracks DESC;

El equivalente en pandas sería df.groupby('GenreId').agg(...) — misma idea, sintaxis distinta.

Autocomprobación
1. ¿Qué necesitas para calcular el promedio de precio POR categoría?
2. ORDER BY total DESC ordena...
5

JOINs: combinar tablas

Un modelo relacional reparte la información en varias tablas para no repetir datos. Los JOIN son la forma de volver a juntarlas cuando una query necesita campos de más de una tabla.

Los cuatro tipos

JOINQué conservaCuándo usarlo
LEFT (OUTER)Todas las filas de la tabla izquierda, aunque no haya match en la derechaEl más frecuente en análisis de datos
RIGHT (OUTER)Todas las filas de la tabla derechaPoco usado — equivale a un LEFT invirtiendo el orden de las tablas
INNERSolo las filas que cruzan en ambas tablasCuando te interesa solo lo que existe en los dos lados
FULL OUTERTodo lo de ambas tablas, con o sin matchExcepcional, pero es habitual en según qué empresa o proyecto
 
SELECT c.Name, i.InvoiceId, i.Total
FROM customers c
LEFT JOIN invoices i ON c.CustomerId = i.CustomerId;

🧪 Pruébalo tú mismo

Dos tablas de ejemplo: customers (4 clientes) e invoices (4 facturas). Luis e Iker no tienen ninguna factura; la factura 104 pertenece a un cliente (id 5) que no existe en customers. Elige un JOIN y mira qué filas aparecen.

ClienteCustomerIdInvoiceIdTotal

🔗 El mismo JOIN, en pandas

pd.merge(
    clientes, facturas,
    on="CustomerId",
    how="left"
)

how en merge() mapea directo a los tipos de JOIN: "left", "right", "inner", "outer" (full).

⚠️ Errores más comunes

Conectar a una base que no existe no da error — crea una vacía en silencio. Un error en la query (tabla o campo mal escrito) sí lanza OperationalError, con un mensaje descriptivo de dónde está el problema.

Lo importante Elige el JOIN según qué filas no te puedes permitir perder: si necesitas conservar todos los clientes aunque no hayan comprado nunca, es LEFT; si solo te interesan los que sí compraron, es INNER.
Autocomprobación
1. Quieres conservar TODOS los clientes, aunque no tengan facturas. ¿Qué JOIN usas?
2. ¿Cuál es el equivalente de un JOIN en pandas?
6

Gestión de bases de datos

Hasta ahora solo leías datos. Estas sentencias los crean, modifican y borran — con más responsabilidad, porque no tienen un "deshacer" automático.

CREATE

Crea una base de datos o tabla nueva, definiendo columnas y tipos.

INSERT

Añade filas nuevas a una tabla existente.

UPDATE

Modifica valores de filas ya existentes — siempre con WHERE, o actualizas la tabla entera.

DELETE

Borra filas — igual de peligroso sin WHERE que un UPDATE sin filtro.

UPDATE tracks
SET UnitPrice = 1.29
WHERE TrackId = 42;   -- sin WHERE, cambia TODAS las filas

DELETE FROM tracks
WHERE TrackId = 42;
Regla de oro Antes de un UPDATE o DELETE, corre el mismo WHERE dentro de un SELECT primero — así ves exactamente qué filas vas a tocar antes de tocarlas.

También puedes borrar columnas enteras o tablas completas (DROP TABLE) — operaciones irreversibles, úsalas con cuidado.

Autocomprobación
1. ¿Qué pasa si haces UPDATE tabla SET campo = valor SIN WHERE?
2. ¿Qué sentencia elimina una tabla completa?
