Git = sistema de control de versiones distribuido. Registra el historial completo de cambios, permite trabajar en paralelo y volver a cualquier punto anterior.

Git ≠ GitHub. Git corre en tu máquina. GitHub es la plataforma en la nube que aloja repos y añade herramientas de colaboración (también GitLab, Bitbucket).

Directorio de trabajo → Staging Area → Repositorio (.git) (tus archivos) git add git commit
git config --global user.name "Nombre"
git config --global user.email "email@..."
git init                    # inicia repo
git status                  # ver estado
git add .                   # staging
git commit -m "mensaje"     # commit

.gitignore — indica qué no rastrear nunca. Usar gitignore.io.

git log --oneline --graph --all   # árbol visual
git diff --staged                 # cambios en staging
git restore archivo.txt           # descartar cambios (!)
git restore --staged archivo.txt  # sacar del staging
git revert <hash>                 # deshacer commit (seguro)
git reset --soft HEAD~1           # deshacer commit, guardar staging
⚠ git reset --hard borra cambios permanentemente.

git merge feature/x           # desde main: fusionar

Fast-forward: destino sin commits nuevos → solo mueve puntero.
Merge commit: ambas ramas tienen commits → crea commit nuevo.

git merge --no-ff feature/x   # fuerza merge commit (recomendado)
git merge --squash feature/x  # aplasta todos en uno

Conflicto: edita el archivo manualmente, elimina los marcadores <<<, luego:

Stash: guardar trabajo sin commit → git stash / git stash pop

Pull Request: propuesta de cambio. Rama feature → main. Un compañero revisa → aprueba → merge.

Fork: copia del repo en tu cuenta para contribuir sin permisos directos.

main: ●──────────────────────●─────────● \ ↗ \ ↗ feature: ●──●──●(PR) ●──●──●(PR)

Solo main como rama permanente. Todo trabajo en feature/*. PRs directamente a main. Sin develop, sin hotfix, sin release.

Ideal para: proyectos de bootcamp, equipos pequeños, CI/CD, cuando cada merge a main es un despliegue.
git switch main && git pull
git switch -c feature/nueva-func
# ... commits ...

# → abrir PR en GitHub: feature/nueva-func → main

## Checklist
- [ ] El código funciona sin errores
- [ ] Docstrings en todas las funciones y clases
- [ ] Sin print() de debug
- [ ] Sin valores hardcoded
- [ ] He hecho rebase/merge de main antes del PR

Closes #N
Al revisar el PR de tu compañero, busca:

🔍 ¿El código hace lo que dice el PR?
🔍 ¿Hay valores hardcoded que deberían estar en variables.py?
🔍 ¿Hay print() de debug olvidados?
🔍 ¿Las funciones tienen docstrings?
🔍 ¿Hay casos edge sin manejar?
🔍 ¿Los nombres de variables son descriptivos?

Al comentar, sé específico:
❌ "Esto no me gusta"
✅ "Este 10 debería ser BOARD_SIZE de variables.py"
✅ "¿Qué pasa si x < 0? Falta validar el rango"
