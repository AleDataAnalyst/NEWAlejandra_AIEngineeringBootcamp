1

FastAPI y APIs para sistemas de IA

Antes la demo era python main.py --ask "..." o un Streamlit en localhost. Ahora el mismo cerebro se expone por HTTP: otros clientes (Swagger, curl, Postman, un front) pueden hablar con él sin importar su código.

Capas y responsabilidades

CapaResponsabilidadEjemplo
ClientePregunta y muestra resultadoSwagger, curl, Postman
APITraduce HTTP ↔ Python (rutas, schemas, errores)POST /ask + AskIn
Lógicaresponder / procesar_turno (RAG, agente, tools)Lo del S10–13 sin tocar

HTTP y familias de códigos

2xx OK

200 respuesta, 201 creado. El flujo normal del /ask.

4xx cliente

400 (vacío tras strip), 404 (hilo inexistente), 422 validación Pydantic automática.

5xx servidor

500 / 502 / 503. Mensaje corto al cliente; traza solo en logs.

App mínima + Swagger

from fastapi import FastAPI

app = FastAPI(title="Demo IA")

@app.get("/health")
def health():
    return {"status": "ok"}

# $ uvicorn app:app --reload --port 8000
# → http://127.0.0.1:8000/docs  (Swagger)

Contrato AskIn / AskOut

from pydantic import BaseModel, Field

class AskIn(BaseModel):
    pregunta: str = Field(min_length=1, max_length=2000)
    thread_id: str | None = None
    auto_aprobar: bool = True

class AskOut(BaseModel):
    respuesta: str
    thread_id: str
    done: bool = False
    pendiente_hitl: bool = False
    error: str | None = None

Health, errores y .env

GET /health

Pulso del servicio: no llama al LLM. Útil para liveness checks y para que oncall sepa si el proceso vive. Metadatos no sensibles OK: {"status":"ok","storage":"sqlite"}.

HTTPException

Código + mensaje corto al cliente. 404 si no existe hilo; 400 si pregunta queda vacía tras strip; 422 lo da Pydantic solo.

.env + config.py

GEMINI_API_KEY, DATABASE_URL, DEBUG. Nunca en el repo; nunca en el JSON de error. En PaaS → panel del servicio.

Middleware (idea)

Capa que envuelve peticiones y respuestas antes/después de las rutas: CORS si un front en otro origen la llama, logging de latencia, auth, gzip. En este sprint rara vez lo tocáis — es vocabulario para S15–16.

Errores típicos Confundir 400 con 422 (422 lo pone Pydantic si el JSON no cumple el schema; 400 lo pones tú por regla de negocio) · devolver la API key en el mensaje de error · hardcodear GEMINI_API_KEY en app.py · subir .env al repo · olvidar .env en .gitignore.

Integración de RAG / Agents en el backend ★

En S10–13 ya separasteis UI y lógica. En S14 el dibujo es el mismo con un eslabón HTTP más: la UI deja de ser el dueño del cerebro. El core = API; Streamlit, si vuelve, será solo un cliente HTTP.

Antes vs ahora

S10–13
[Browser] → Streamlit ──import──► procesar_turno() / agente

S14 (ahora)
Cliente (Swagger, curl, Postman…)
        ↓  HTTP
     FastAPI  →  procesar_turno() / agente

Del CLI a la API

from src.agent import procesar_turno

@app.post("/ask", response_model=AskOut)
def ask(body: AskIn) -> AskOut:
    out = procesar_turno(body.pregunta)   # misma lógica que CLI
    return AskOut(
        respuesta=out["respuesta"],
        thread_id=body.thread_id or "default",
        done=out.get("done", False),
    )

Checklist de migración

Preparación

  • La lógica vive en un módulo importable (src/…), no sólo en un notebook
  • Devuelve un dict (o Pydantic) estable
  • FastAPI solo traduce HTTP ↔ ese dict
  • No reescribes el grafo LangGraph — lo envuelves

Contrato POST /ask

  • Body mínimo: pregunta (+ thread_id si hay hilos)
  • Respuesta corta: respuesta, thread_id, done
  • Extras (fuentes, pendiente_hitl, error) solo si los pide el cliente
  • Elige /ask o /chat y sé consistente

Quién decide qué (límites, timeouts, secrets)

ControlDóndePor qué
Longitud / forma de preguntaPydantic / rutaEl cliente puede mandar basura
Timeout HTTP al LLMCliente HTTP / wrapper del LLMLa red / el modelo pueden colgarse
max_turns / doneLógica del agente (S11–13)Es decisión de negocio del grafo
API keysVariables de entornoNo pueden vivir en el repo
Regla del bootcamp Pydantic valida la forma; la lógica del agente decide el contenido; el LLM solo propone. El modelo no decide “¿paro ya?” si Python puede calcularlo.

Dejamos Streamlit como núcleo

El core de la app es ahora la API FastAPI. Un front futuro (Streamlit, React, móvil…) sería sólo un cliente HTTP que hace httpx.post(f"{API_URL}/ask", json=...): cambia la URL, no la lógica.

Errores típicos Reescribir el grafo dentro de la ruta en vez de importarlo · meter el prompt en app.py · usar el LLM para decidir banderas de control · exponer tracebacks completos o la API key al cliente · duplicar max_turns en API y agente.

Persistencia con SQL y SQLModel

Sin DB, al reiniciar uvicorn se borra todo lo que vivía en RAM (incluido el MemorySaver). Guardamos lo justo con SQLite + SQLModel: un hilo (thread_id) y los mensajes user / assistant.

Dos capas

CapaRolEn este sprint
SQLModelCómo habláis vosotros con la DB (clases Python, Session)Lo escribís vosotros
RDBMSDónde viven los datos y quién ejecuta el SQLSQLite (historial.db)

Misma API de código; cambia sobre todo la URL del motor. En producción (S15+) podríais apuntar a Postgres sin reescribir los modelos: postgresql+psycopg://usuario:password@host:5432/ia_demo.

SQL mínimo (lo que hay debajo)

SELECT role, content
FROM   message
WHERE  thread_id = 'demo-aire'
ORDER BY id;

INSERT INTO message (thread_id, role, content)
VALUES ('demo-aire', 'user', '¿Cómo está el NO2?');

PK identifica una fila (en conversation suele ser el propio thread_id; en message, un entero autoincremental). FK message.thread_id → conversation.id enlaza el 1–N.

Modelos del historial

from datetime import datetime, timezone
from typing import Optional
from sqlmodel import Field, SQLModel

def _now() -> datetime:
    return datetime.now(timezone.utc)

class Conversation(SQLModel, table=True):
    id: str = Field(primary_key=True, max_length=100)
    created_at: datetime = Field(default_factory=_now)

class Message(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    thread_id: str = Field(foreign_key="conversation.id", index=True, max_length=100)
    role: str     # 'user' | 'assistant'
    content: str
    created_at: datetime = Field(default_factory=_now)

Engine, sesión y arranque

from sqlmodel import SQLModel, Session, create_engine
from src.models import Conversation, Message  # registran las tablas

engine = create_engine(DATABASE_URL, echo=False)

def ensure_schema() -> None:
    SQLModel.metadata.create_all(engine)

def get_session() -> Session:
    return Session(engine)

Llamad a ensure_schema() al arrancar la app (lifespan). echo=True imprime el SQL en consola — útil para aprender.

Un turno = 2 Message + 1 Conversation si falta

def save_turn(thread_id: str, pregunta: str, respuesta: str) -> None:
    with get_session() as session:
        conv = session.get(Conversation, thread_id)
        if conv is None:
            session.add(Conversation(id=thread_id))
            session.commit()

        session.add(Message(thread_id=thread_id, role="user", content=pregunta))
        session.add(Message(thread_id=thread_id, role="assistant", content=respuesta))
        session.commit()

Orden del turno con historial

1
Validar body (Pydantic ya hace la mayoría; añade reglas de negocio como «pregunta no vacía tras strip»).
2
Llamar a la lógica de IA (procesar_turno / responder).
3
Persistir si la lógica respondió OK. Si falla el LLM, no insertes una respuesta vacía.
4
Devolver JSON con AskOut. El cliente ya puede llamar a GET /threads/{id}/messages.

Dos almacenes distintos

Pregunta del usuario
        │
        ├─► SQLModel → RDBMS (SQLite / Postgres)   (quién preguntó qué — historial)
        │
        └─► Vector DB                              (chunks del corpus — RAG)

El historial tabular y los embeddings del RAG viven en sistemas distintos: uno es texto estructurado por hilo, el otro es búsqueda semántica. No se sustituyen.

Errores típicos Cambiar models.py tras arrancar y no borrar historial.db (las tablas no se recrean solas) · olvidar el commit · dejar la URL sqlite:/// hardcodeada en vez de leer DATABASE_URL · persistir aunque el agente haya fallado · usar session.query antiguo en vez de select.
